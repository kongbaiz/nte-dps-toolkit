# Tauri + React 迁移第 24 步：空幕页面 UI

## 本阶段范围

空幕页面继续采用两步迁移，本阶段只完成第 1 步 React UI。页面使用资源目录中的真实装备元数据、
图标和角色头像构造少量预览数据，用于验证信息密度和响应式布局；库存快照、筛选权威状态、导入
导出、角色套装和 Mod Plugin 装配事务均留到第 2 步接入。

本阶段不修改 Rust 空幕领域规则、装备状态、文件协议、Plugin IPC、旧 egui 页面或其他 Console
页签。所有需要 Rust 或原生文件对话框的操作都明确禁用。

## 页面结构

- Console 侧栏启用“空幕”，页面由 React 19.2 `Activity` 管理可见性；
- 页头显示“界面预览 / 数据将在第 2 步接入”，避免把 fixture 表现成实时库存；
- 工具栏保留筛选、清除筛选、可见/总数、驱动计算器导出和角色装备入口；后两项保持禁用；
- 筛选面板保留旧 egui 的按角色、驱动块、卡带、品质和副词条分组；组内为 OR，分组之间为
  AND，副词条要求全部命中；
- 卡片保留装备图标、名称、等级、品质、锁定、弃置、已装备角色、属性行与套装效果；
- 套装详情由可聚焦的 HTML Tooltip 展示，装备图标和角色头像复用共享资源；
- 装备网格使用 `auto-fill + minmax`，随可用客户区宽度自动增加列数，不依赖固定断点列数；
- 空筛选结果使用统一 Empty，工具栏和筛选区采用平面分隔，避免额外堆叠 Card。

## 第 2 步接入边界

下一步将复用现有 Rust 空幕库存与装备规则，新增稳定、版本化 DTO 和 typed client。React 只消费
聚合库存快照并发出筛选、导入导出、角色套装及装备管理意图；文件对话框、库存校验、Plugin
能力检查和装备事务继续由 Rust 负责。实时变化使用合并后的有序批次或状态代次，不逐物品、逐帧
调用 `invoke`。

## 人工验收清单

入口：启动 Console，点击侧栏“空幕”。

1. 页头应显示“界面预览”，导出和角色装备按钮应禁用，并提示数据将在第 2 步接入；
2. 打开筛选，分别验证角色、驱动块、卡带、品质和多个副词条；清除筛选后恢复 6 件预览装备；
3. 检查装备图标、品质边条、等级、锁定/弃置状态、属性和已装备角色头像；
4. 鼠标悬停或键盘聚焦卡带套装名称，检查套装名称与效果提示不被卡片裁切；
5. 将窗口依次调整为 760、900、1100、1440 像素宽，确认工具栏换行、筛选分组和卡片列数合理，
   没有横向溢出或底部内容截断；
6. 在 100%、125%、150% DPI 下快速调整窗口大小，确认卡片和筛选按钮没有闪烁或越界；
7. 切换简体中文、日文和英文，核对装备资源名、属性、筛选、空状态和禁用操作文案；
8. 在 Settings、History、Timeline、Skills、空幕和 Mod Studio 间反复切换，确认筛选与展开状态保留，
   隐藏页面没有活跃副作用；
9. 与旧 egui 空幕页对照工具栏、筛选层级、装备状态、属性行与套装信息，不提前验收第 2 步功能。

UI 由人工启动验收；自动化验证不替代窗口缩放、DPI、资源显示和旧界面对照。
