# Tauri 迁移第 33 步：旧版交互与视觉语义补齐

## 范围

本步只修复用户对照旧 egui 界面确认的四项迁移差异：深渊队伍导入区、抓包文件加载过渡、
HUD 编辑态排序与头像，以及角色固定颜色。抓包解析、战斗归并、更新协议、历史格式和现有
egui 对照入口保持不变。

## 修复结果

### 深渊“导入当前队伍”

- Rust 快照按上下半场显式提供当前队伍是否可导入，React 不再通过本地数据猜测按钮状态。
- 已导入队伍的最多四个成员头像恢复到线路标题行，旁边显示预计时间、DPS 和清除按钮。
- 无预测队伍时，只有当前权威战斗状态可导出该半场队伍才显示“使用当前队伍预测”；文件导入仍
  独立保留。原先标题下方重复的队伍卡片区已移除。

### 抓包文件加载过渡

- 回放任务进行期间，主 DPS 窗口保留标题和控制区，只显示加载动画与说明，不展示逐步变化的
  旧结果或半成品结果。
- `replayRunning` 结束后的同一份 Rust 完整快照才恢复轮次、汇总和角色排行；没有在 React
  复制回放完成判定。

### HUD 编辑态

- 编辑态中的每个实际 HUD 模块恢复可拖拽标题条和虚线边界，可直接拖到目标模块上半或下半
  完成排序；键盘上下键提供同一排序能力。
- 排序继续调用既有 typed command，并由 Rust 保存 `HudConfig.module_order`；穿透展示态不绘制
  编辑标题条。
- 实际角色行恢复资源头像；缺图时才显示带角色色的首字占位。

### 角色固定颜色

- 角色资源加载时复用旧版头像像素加权取色算法，为缺少显式 `color` 的角色生成稳定十六进制色。
- 主 DPS 与 HUD DTO 都消费同一份 Rust 资源颜色；未知角色才使用与旧 Zinc 主题一致的固定调色板
  和 FNV-1a 回退，不再按角色 ID 直接取模。
- 已增加回归断言：角色 1010 的现有头像投影保持为 `#A72648`。

## 契约边界

- 深渊数值契约由 v1 提升到 v2，新增 `currentTeamAvailable.upper/lower`。
- 技术快照契约由 v4 提升到 v5，HUD 快照由 v2 提升到 v3，角色行新增可选 `color`。
- 根 crate 的 `desktop` feature 启用已有可选 `image` 依赖，让 Tauri 与 egui 共用资源取色实现；
  CLI-only feature 不启用该依赖，也不引入窗口或 WebView 依赖。

## 人工验收清单

1. **深渊队伍**：分别在有/无当前战斗队伍时打开上下半场；确认按钮可用性正确。导入后头像、
   预计时间、DPS、清除按钮均在标题行，且没有下方重复队伍卡片。
2. **抓包回放**：用较大的 `.pcapng` 和 `.json` 文件导入；加载期间只见动画，完成前不出现旧
   统计或逐步增长内容，完成后一次显示最终轮次与排行；错误时恢复可操作状态并显示错误。
3. **HUD 排序**：关闭穿透，直接拖动标题、摘要、状态、角色排行和时间线模块的标题条到目标前后；
   关闭并重开 HUD 后顺序保持。用键盘聚焦标题条后按上下键，结果一致。
4. **HUD 头像**：实战数据下核对角色头像与主 DPS 窗口一致；资源缺失时显示首字占位，预览行仍
   显示 A～D 占位。
5. **颜色一致性**：同一角色在主 DPS、HUD、占比条和百分比文字中保持同一颜色；与旧 egui
   界面逐角色对照，重点核对 1010 为 `#A72648`。
6. **显示环境**：检查简中、日文、窄窗口、100%/125%/150% DPI、多显示器，以及 HUD 的透明、
   穿透、置顶、拖动窗口和从 Console 恢复编辑状态。

本步没有启动桌面 UI；以上项目保留给人工对照旧 egui 界面验收。
