# Tauri + React 迁移第 28 步：封包页面完整迁移

## 本阶段范围

本阶段一次完成 Console“封包”页的 UI 与功能迁移。抓包、协议解析、命中归并和调试封包
生成继续由 Rust 负责；React 只消费有界的已解码投影，执行搜索、命中筛选、展开与滚动跟随。

## 契约与传输边界

- 实时抓包服务启用既有 `FullDebug` 事件，但可靠事件与可丢弃调试事件分别进入有界队列；
- `CombatState` 增加独立封包 generation，封包或统计质量变化不会让 HUD、技能或时间线重复投影；
- `core::packets` 只投影旧封包页实际展示的时间、方向、端点、长度、声明 ID、命中数、备注和解码文本；
- 原始 payload、十六进制内容和 payload preview 不跨越 Tauri 边界；
- Rust 保留环中只取最新 500 条，Channel 每 100 ms 合并发送；游标仍在保留范围内时只发送增量，
  切换抓包会话、游标落后或超过窗口时发送完整替换快照；
- generation、封包序号和累计包数以十进制字符串跨越 JavaScript 安全整数边界；
- Tauri command、Channel 和取消订阅均经过 typed client，页面不直接调用裸 `invoke()`。

## 页面行为

- Console 侧栏启用“封包”，页面由 React `Activity` 管理可见状态；隐藏时释放 Channel，返回时
  先读取当前 Rust 快照再恢复订阅；
- 保留旧页的 IP / ID / 协议名称搜索、“仅显示命中包”、事件/封包/队列统计和逐包展开；
- 列表默认跟随最新封包；用户向上滚动后暂停跟随，回到底部后自动恢复；
- 每行显示时间、方向、端点、字节数、声明 ID 和命中数，展开后显示备注及只读自动解析文本；
- loading、初始错误、空数据、筛选无结果和流中断均有独立状态；流错误使用顶部居中浮层，
  不挤占封包列表；
- 列表使用稳定封包序号、延迟搜索和浏览器内容可见性裁剪，避免 500 条展开节点持续参与绘制；
- 简体中文和日文补齐本阶段新增文案，未知方向仍保留 Rust 原值，便于协议诊断。

## 人工验收清单

入口：启动 Console，开始实时抓包后点击侧栏“封包”。

1. 未开始抓包时确认显示空状态；开始后状态依次显示启动中、实时，停止后显示已停止；
2. 进入联网场景产生通信，确认列表自动追加且最多显示最新 500 条，事件/封包/队列统计更新；
3. 搜索 IP、端口片段、声明 ID、方向和协议文本，确认结果与旧 egui 页面一致；
4. 打开“仅显示命中包”，确认只保留命中数大于 0 的封包；
5. 展开多条记录，检查备注和自动解析文本；确认页面与前端错误中没有原始 payload 或十六进制载荷；
6. 向上滚动停留在旧记录，确认新封包不会抢回滚动位置；回到底部后确认自动跟随恢复；
7. 离开封包页再返回，确认订阅已重建并从当前 Rust 快照恢复现有记录，没有重复行或断裂；
8. 在高包速下观察队列与列表更新，确认 Console、HUD、技能和时间线没有因每个调试包整体刷新；
9. 在最小窗口、宽屏及 100%、125%、150% DPI 下检查端点截断、筛选换行、展开文本和滚动条；
10. 切换简体中文、日文和英文，对照旧 egui 页确认信息层级、筛选语义和展开内容。

桌面 UI 仍由人工启动验收；自动化验证不替代真实 Npcap、高包速、DPI 和长时间滚动检查。
