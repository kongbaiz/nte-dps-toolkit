# Tauri + React 迁移第 30 步：诊断页面完整迁移

## 本阶段范围

本阶段一次完成 Console“诊断”页的 UI 与功能迁移。Npcap 枚举、游戏连接探测、实时抓包、
PCAPNG/JSON 回放、解析质量统计和导出继续由 Rust 实现；React 只展示稳定投影并发出操作意图。
旧 egui 诊断页继续保留为人工对照。

## 契约与执行边界

- 原诊断检查提升为 `core::diagnostics`，输出稳定状态、message key 与参数；迁移期 egui 通过
  兼容适配器继续复用同一规则；
- `LiveCaptureService` 保留最近一次已完成的原始抓包，并让 PCAPNG/JSON 导入复用现有 engine
  事件和 reducer，不在 Tauri 或 TypeScript 中复制解析规则；
- Tauri 新增版本 1 Diagnostics DTO、六个 typed command 和 500 ms 变更驱动 Channel；
- Channel 同时观察抓包生命周期、封包代次和诊断报告代次，数据变化时主动发送完整有界快照，
  空闲时不重复序列化；React `Activity` 隐藏页面时清理订阅；
- 原生文件选择和保存窗口由 Windows/Rust 层持有，取消选择不会产生成功提示；导入前后均检查
  抓包/回放是否空闲；
- WebView 不接收原始载荷、本机完整路径或内部错误链。64 位计数使用十进制字符串，前端在
  typed client 边界校验版本、枚举、数量和文本长度。

## 页面行为

- 页头提供“运行诊断”和“复制脱敏报告”；错误使用顶部居中浮层，不占用内容空间；
- 环境区使用响应式扁平指标带展示网卡、本地 IP、游戏连接、实际 BPF 和原始抓包状态；
- 文件工具栏接入 PCAPNG/JSON 导入、解析 JSON 导出和完整 PCAPNG 另存为；按钮根据 Rust
  权威状态启用，所有保存操作都会先打开原生位置选择窗口；
- 运行检查按失败、警告、通过排序，明细和建议保持可见；复制报告只包含状态、标题和建议，
  不复制检查 detail、原始包或路径；
- 解析质量区展示包/命中、方向、角色、技能、GameplayEffect、时停、深渊和服务端校正计数；
- 首次 loading、命令错误、尚未运行诊断和流中断均有独立状态；宽窗口三列，窄窗口自动折行。

## 人工验收清单

入口：启动 Console，点击侧栏“诊断”。

1. 首次进入确认显示 loading，随后出现环境、文件操作、未运行诊断 Empty 和解析质量；
2. 进入游戏场景后点击“运行诊断”，对照旧 egui 页检查 Npcap、游戏连接、抓包状态、原始抓包、
   伤害解析、承伤记录和服务端校正状态；
3. 开始实时抓包并产生网络包/伤害，确认页面主动更新抓包阶段和解析质量，不需要手动刷新；
4. 停止抓包后点击“导出解析 JSON”和“完整 PCAPNG 另存为”，确认先出现系统保存位置窗口，
   取消不写文件，选择路径后文件可重新导入；
5. 分别导入 PCAPNG 和 Capture JSON，确认先出现系统文件窗口，回放通过同一 reducer 清空并
   重建当前统计，页面显示对应来源和回放状态；
6. 点击“复制脱敏报告”并粘贴检查：包含检查状态和建议，不包含用户目录、网卡内部名称、
   原始载荷、完整错误链或资源 key；
7. 在抓包或回放进行中确认文件操作禁用；模拟 Channel 中断时确认错误浮层居中且页面不位移；
8. 离开诊断页再返回，确认隐藏期间订阅已释放，返回后从 Rust 当前快照恢复；
9. 在最小窗口、宽屏及 100%、125%、150% DPI 下检查指标折行、长 BPF 截断、检查行、滚动和
   焦点轮廓；
10. 切换简体中文、日文和英文，确认页头、环境、操作、检查状态与解析质量文案同步更新。

桌面 UI 仍由用户人工启动验收；自动化验证不替代 Npcap、原生文件对话框、真实游戏连接、
回放文件、DPI 和发行构建检查。
