# Tauri + React 迁移第 29 步：资源页面完整迁移

## 本阶段范围

本阶段一次完成 Console“资源”页的 UI 与功能迁移。资源覆盖检查继续由 Rust 读取软件自身
`res/` 运行资源；不会访问游戏客户端导出目录、资源导出 key 或外部维护工具。旧 egui
页面继续保留为人工对照。

## 契约与执行边界

- 原 `support::resource_audit` 实现提升为 `core::resource_audit`，并由迁移期 egui 兼容
  re-export 继续复用，同一审计规则没有 TypeScript 副本；
- 该 core 模块只在 `desktop` 或 `gui` feature 下编译，CLI-only 依赖边界保持不变；
- Tauri 新增版本 1 Resources DTO，只投影计数、严重级别、分类、资源 ID、展示名、稳定
  message key/参数、建议来源和 Rust 生成的脱敏报告；
- 动态文件与 JSON 错误在适配边界拆为稳定 key 和有界参数；前端对枚举、文本长度、数组数量
  和契约版本执行一次运行时校验；
- 资源扫描通过 Tauri blocking worker 执行，不阻塞 WebView 主线程；页面不直接调用裸
  `invoke()`，只使用 typed client；
- 扫描是低频显式查询，不增加 Channel 或轮询。React `Activity` 隐藏页面时清理 Effect，
  返回时保留上次快照；只有首次进入和用户点击刷新才重新检查。

## 页面行为

- Console 侧栏启用“资源”，保留旧页的刷新检查、脱敏报告复制、错误/警告、角色/技能、
  深渊/反应摘要，以及严重级别和分类筛选；
- 摘要使用一条响应式指标带而不是堆叠卡片；资源缺口使用扁平分隔列表，宽窗口展示三列，
  窄窗口自动折为上下信息；
- 列表显示严重级别、分类、资源 ID、展示名、问题说明和建议来源；已知审计消息通过英文
  稳定 key 在简体中文、日文和英文界面本地化；
- 首次 loading、命令错误、无资源缺口、筛选无结果均有独立状态；手动刷新时保留现有结果，
  不切回全页骨架；
- 脱敏报告仍由 Rust 生成，并沿用最多 80 条、隐藏本机绝对路径的既有规则；
- 长列表使用稳定组合 key 和 `content-visibility` 裁剪，筛选只处理当前有界 DTO。

## 人工验收清单

入口：启动 Console，点击侧栏“资源”。

1. 首次进入确认显示检查骨架，完成后出现四组摘要、筛选栏和缺口列表；
2. 点击“刷新检查”，确认按钮显示忙碌状态但旧结果不消失，完成后原位更新；
3. 分别选择全部、仅错误、仅警告，以及角色、技能、GE、深渊、反应、文件分类，确认结果
   与旧 egui 页一致；
4. 点击“复制脱敏报告”并粘贴检查：包含计数和最多 80 条缺口，不包含用户目录、游戏导出
   路径、资源 key 或客户端载荷；
5. 临时移走一份可分发测试资源后刷新，确认显示稳定错误文案与相对建议来源；恢复资源后再次
   刷新，确认缺口消失；
6. 离开资源页再返回，确认保留上次结果且没有后台持续扫描；再次手动刷新才产生新检查；
7. 在没有缺口和筛选无匹配两种情况下分别检查 Empty 文案；
8. 在最小窗口、宽屏及 100%、125%、150% DPI 下检查指标换行、筛选控件、长 ID/路径截断、
   列表滚动和焦点轮廓；
9. 切换简体中文、日文和英文，确认页头、筛选、状态、审计说明和已知问题文案均同步更新；
10. 对照旧 egui 资源页确认数量、排序、严重级别、分类、问题和建议来源一致。

桌面 UI 仍由用户人工启动验收；自动化验证不替代打包资源目录、剪贴板权限、DPI 和真实
发行目录检查。
