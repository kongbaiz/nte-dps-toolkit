# Tauri + React 迁移第 26 步：角色数据页面完整迁移

## 本阶段范围

本阶段一次完成 Console“角色数据”页的 UI 与功能迁移。页面继续编辑同一份
`res/data/characters/characters.json`，React 只维护搜索、选择和表单草稿；读取、校验、未知字段保留、
原子写入与写后重载全部由 Rust 执行。

## 契约与数据流

- `core::character_data` 提供前端无关的角色表投影、字段边界校验和单记录原子更新；
- Tauri 提供版本 1 的显式 DTO，generation 跨 JS 使用十进制字符串，命令只允许 Console 窗口调用；
- 页面通过 typed client 加载完整角色目录并保存单条记录，不直接读取文件或调用裸 `invoke()`；
- 保存现有角色时禁止修改 ID；新增 ID、名称、属性、颜色、字段长度和目录上限均在 Rust 信任边界校验；
- 写入只更新已知字段并保留记录中的未来扩展字段，写入成功后重新解析文件再返回快照；
- 运行中的抓包继续使用启动时加载的角色映射，保存后的映射在下次启动时生效，与旧页面语义一致。

## 页面行为

- 侧栏启用“角色数据”，通过 React `Activity` 保留页内搜索和草稿状态，隐藏时清理页面 Effect；
- 工具栏支持新增 ID、重新载入和总数显示；搜索覆盖 ID、中英文名、代号和属性；
- 左侧角色列表显示头像、显示名、英文名、ID、属性与验证状态；右侧编辑 ID、中英文名、代号、
  属性、颜色、头像路径和验证状态；
- 未保存时阻止切换角色或重新载入，错误和成功提示使用顶部居中浮层，不改变页面布局；
- 页面包含 loading、empty、search-empty、load-error 和 mutation-error 状态，并在窄窗口改为上下布局；
- 用户可见文案使用统一 i18n key，简体中文和日文资源已同步。

## 人工验收清单

入口：启动 Console，点击侧栏“角色数据”。

1. 首次进入显示角色总数、头像和名称；搜索 ID、中英文名、代号或属性均能得到正确结果；
2. 选择角色修改名称、属性、颜色、头像路径和验证状态，保存后列表与表单同步更新；重启程序后确认
   抓包、时间线、技能和空幕中的角色映射使用新数据；
3. 输入新 ID 新增角色；验证重复 ID、零/负数/非数字 ID、空名称、非法属性和非法颜色均显示顶部错误；
4. 修改表单后尝试切换角色或重新载入，确认草稿不会被静默覆盖；取消修改恢复保存值；
5. 将窗口调整为最小尺寸和宽屏尺寸，并在 100%、125%、150% DPI 下确认左侧列表与右侧表单
   自适应，无横向溢出或内容截断；
6. 切换简体中文、日文和英文，检查标题、字段、按钮、空状态和错误文案；
7. 与旧 egui 角色数据页对照新增、搜索、编辑、校验、保存和重新载入行为。

桌面 UI 仍由人工启动验收；自动化验证不替代真实文件权限、安装目录写入和重启后的映射检查。
