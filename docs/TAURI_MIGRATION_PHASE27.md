# Tauri + React 迁移第 27 步：加密 INI 页面完整迁移

## 本阶段范围

本阶段一次完成 Console“加密 INI”页的 UI 与功能迁移。AES-256-ECB、PKCS#7、国服/国际服
key、`|SPLIT|` 记录保留、原始行尾和未修改密文复用继续由 Rust 实现；React 只维护编辑草稿、
搜索位置和确认浮层。

## 契约与文件边界

- 原 `support::encrypted_ini` 算法提升为 `core::encrypted_ini`，旧 egui 页面通过 re-export 继续复用；
- Rust 会话保存当前文件、原始明文、原始 key、密文记录、行尾格式和 generation；
- Tauri 提供版本 1 DTO 以及获取、打开、重新载入、保存、清空五个 typed command；
- 打开文件使用归属于 Console 窗口的 Windows 原生 INI 文件选择窗口，取消选择不会覆盖当前草稿；
- 文件上限为 8 MiB；文件内容、generation、key 和保存请求均在 Rust/TypeScript 边界校验；
- 保存使用原子替换并在写入前复用未修改密文记录，写入后返回新的权威快照；
- 错误只向前端暴露稳定 code、message key 和参数，系统错误与本机路径不进入提示。

## 页面行为

- 侧栏启用“加密 INI”，页面由 React `Activity` 保留草稿和搜索状态；
- 支持打开、保存、重新载入、清空、切换国服/国际服 key、编辑明文和全文搜索；
- 上一个/下一个匹配会循环切换并选中编辑器中的对应文本，同时显示行列位置；
- 重新载入或清空前如存在未保存修改，使用顶部确认浮层，确认后才丢弃草稿；
- 打开、保存、重载、未修改和错误均使用顶部居中提示，不改变编辑器布局；
- 页面覆盖首次加载、未打开文件、忙碌、打开取消、命令错误和窄窗口换行布局。

## 人工验收清单

入口：启动 Console，点击侧栏“加密 INI”。

1. 点击“打开 INI”，确认原生窗口只优先显示 `.ini`，取消后当前编辑内容保持不变；
2. 分别打开国服和国际服样本，检查 key、密文行数、路径和解密明文；
3. 修改一行后保存并重新载入，确认修改保留；未修改直接保存时原密文文件保持不变；
4. 切换保存 key 后保存，再次打开确认自动识别新 key；
5. 搜索配置名和值，检查匹配数量、循环上一个/下一个和行列位置；
6. 修改后点击重新载入或清空，确认取消会保留草稿、确认才执行；
7. 测试无权限文件、无效密文、超过 8 MiB 文件和写入失败时的顶部错误；
8. 在最小窗口、宽屏及 100%、125%、150% DPI 下检查编辑器与工具栏无截断；
9. 切换简体中文、日文和英文，并与旧 egui 页面对照打开、编辑、搜索、保存和清空行为。

桌面 UI 仍由人工启动验收；自动化验证不替代真实文件权限、原生文件窗口和样本回读检查。
