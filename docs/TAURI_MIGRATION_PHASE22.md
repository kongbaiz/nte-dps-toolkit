# Tauri + React 迁移第 22 步：技能页面 UI

## 本阶段范围

完成技能页面两步迁移的第 1 步：只迁移 React UI，不新增 Rust 投影、Tauri command、
Channel 或业务规则。本阶段不迁移其他 Console 页签，也不修改技能归因、伤害聚合、资源或
历史逻辑。

## 页面结构

- Console 侧栏启用“技能”，页面继续由 React 19.2 `Activity` 管理显示与隐藏；
- 复刻现有 egui 技能页的信息架构：角色导航、归因伤害、技能项、待映射/候选方向、技能明细和
  待映射诊断；
- 角色导航复用共享角色头像资源，并显示伤害、占比和技能项数量；
- 技能明细以细条进度底纹表达占比，不叠加独立 Card，视觉 token 与设置、历史和时间线保持一致；
- 宽窗口使用角色导航与技能明细双栏；窄窗口把角色导航改成横向滚动，技能行自动换行；
- 页面明确显示“界面预览 / 数据将在第 2 步接入”，当前 fixture 只用于布局验收；
- 角色切换只筛选本地预览数据，所有 Rust 权威数据与技能归因规则保持原状。

## 第 2 步边界

下一步从现有 Rust `SkillBreakdown` 生成 UI-neutral、版本化技能投影，通过 typed command 获取
首屏，并用变更驱动 Channel 发布聚合快照。React 将覆盖 loading、empty、error、重试和订阅
清理，再替换本阶段 fixture；不向 WebView 传输逐 hit 或内部领域状态。

## 人工验收清单

入口：启动 Console，点击侧栏“技能”。

1. 核对页头“界面预览”和“数据将在第 2 步接入”，避免把 fixture 识别为实战数据；
2. 切换整队、真红、哈索尔和娜娜莉，确认技能列表、归因伤害和技能项数量同步变化；
3. 角色头像、伤害、占比、技能名称、类型、命中和进度底纹均清晰，无资源时显示文字回退；
4. 展开待映射诊断，确认未知角色、候选方向、待映射技能和未映射 GE 信息完整；
5. 在 760、900、1100、1440 像素宽度快速缩放窗口，角色导航在窄窗口横向滚动，技能行不被裁切；
6. 在 100%、125%、150% DPI 下检查头像、百分比、长技能名和数值列；
7. 切换简体中文、日文和英文，核对已有翻译和动态技能名称；
8. 对照旧 egui 技能页核对信息层级，并确认页面风格与 Settings、History、Timeline 一致。

UI 由人工启动验收；自动化验证不替代窗口缩放、DPI 和旧界面对照。
