# 抓包模式与 UE Tools 插件模式

## 当前实现

- `UiConfig.data_mode` 默认为 `packet_capture`；旧配置没有此字段时仍使用抓包。
- Mod 工坊的控制面板通过风险确认切换到 `plugin`。切换先停止当前采集，再保存模式；不清空已有记录，不自动开始下一场采集。
- 抓包模式只使用现有 Npcap → Engine → Reducer 链路，不探测旧 Mod IPC。
- 插件模式使用 Toolkit v1 共享内存 → 有界报告适配 → 同一 EngineEvent/Reducer。复用现有采集会话的 owner、停止与投递屏障，不启动 Npcap；连接失败不回退抓包。
- 控制面板显示宿主实际报告的加载状态、启用/禁用/重载结果、战斗汇总与日志设置。安装完成不等于已加载；超时后结果未知，不自动重试变更命令。
- 代码编辑器、脚本 CRUD/执行通道及旧加载器启动入口已移除。旧装备写入入口返回不支持；历史文件解码与历史来源枚举保留，不将旧功能伪装成 Toolkit 能力。

## 已编译插件部署与市场

本工程不编译或依赖 UE Tools 源码。当前对接的已编译包为 `d3d12.dll` 加 `plugins/NTE_PluginCombat.dll`，无内置界面，Toolkit 协议 v1、战斗报告 schema 14。

先按该二进制包的部署说明安装宿主，再在控制面板选择包含 `HTGame.exe` 和 `d3d12.dll` 的游戏目录。若目录仍有旧 `dwmapi.dll`，本程序拒绝作为新插件目录使用，不自动覆盖或删除用户 DLL。返回抓包模式只停止插件数据消费，不能承诺卸载已进入游戏进程的宿主；退出游戏后按部署说明移除。

Mod 市场保留浏览、搜索、下载和升级方式。新目录 schema 为 5，使用 `/mods/v2/`；包名为 `<id>-<version>.dll`，安装为 `plugins/<id>.dll`。沿用签名目录与 HTTPS 来源校验，并验证大小、SHA-256、AMD64 PE32+ DLL。非 DLL 脚本被拒绝，写入沿用已有原子替换实现。公开签名目录及二进制条目尚需发布，未发布时显示下载/目录错误，不生成虚假条目。CI 可通过 `NTE_TOOLKIT_BUNDLE` 提供已编译私有包；未设置时只构建桌面与 CLI，不打包旧加载器。

## 数据准确性边界与验收状态

- 当前每秒读取一次完整的、有大小上限的原生报告，并只投递新增事件；不属于无损逐事件推送。命中原生角色 ID 且来源为 direct/correlated 才确认角色，inferred/unknown 保持未知；伤害保留原始浮点值。
- Toolkit 当前事件数组是保留窗口，缺少稳定的事件 ID、逐事件 revision 和完整增量游标。发现丢失、保留事件修订或会话切换时停止并报错，保留已收到数据，不补零、不猜测、不混入抓包结果。
- 目前接入伤害事件、角色、技能、目标与来源质量。原生报告中的治疗、完整属性、效果历史和游戏时钟尚未全部进入现有 read model；因此不能声称“信息最全”或“所有数据最精确”已完成。
- 实际已编译 DLL 的 Describe、插件列表、禁用/启用、日志设置、schema 14 报告与关闭已通过隔离进程验证。该进程不是游戏，SDK 未兼容，不能证明真实战斗数据正确。
- 上线前仍须实际游戏验证来源排他、延迟、完整性、归属、会话切换与停止；如要求长期无损采集及晚到修订，需要闭源插件提供相应增量接口，再扩展本适配层，不能靠客户端测试代替。
