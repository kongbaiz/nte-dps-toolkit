# 抓包模式与 UE Tools 插件模式

## 当前实现

- `UiConfig.data_mode` 默认为 `packet_capture`；旧配置没有此字段时仍使用抓包。
- 首页数据来源入口通过风险确认切换到 `plugin`。切换先停止当前采集，再保存模式；不清空已有记录，不自动开始下一场采集。
- 抓包模式只使用现有 Npcap → Engine → Reducer 链路，不探测旧 Mod IPC。
- 插件模式使用 Toolkit v1 共享内存 → 有界报告适配 → 同一 EngineEvent/Reducer。复用现有采集会话的 owner、停止与投递屏障，不启动 Npcap；连接失败不回退抓包。
- 控制面板管理宿主加载方式、确认状态、加载和卸载；插件自身功能按能力开放，不提供手动目录选择、宿主日志等级或通用重载。安装完成不等于已加载；超时后结果未知，不自动重试变更命令。
- 代码编辑器、脚本 CRUD/执行通道及旧加载器启动入口已移除。旧装备写入入口返回不支持；历史文件解码与历史来源枚举保留，不将旧功能伪装成 Toolkit 能力。

## 已编译插件部署与市场

本工程不编译或依赖 UE Tools 源码。当前对接的已编译包为 `d3d12.dll` 加 `plugins/NTE_PluginCombat.dll`，无内置界面，Toolkit 协议 v1、战斗报告 schema 14。

组件全部由 Mod 市场下载到程序旁的 `mods/` 托管目录：宿主和插件位于 `game/`，Loader 位于 `tools/`，驱动位于 `driver/`。无需手动选择路径。控制面板的宿主页选择代理或 Loader 加载。代理方式自动识别唯一游戏目录并安全部署；未知已有文件不覆盖，部署后重启游戏。Loader 使用托管组件，标准 UAC 及驱动生命周期仍由原生 Loader 管理。

新版签名目录为 `https://dps.o-na-ni.com/mods/v3/catalog.json`，schema 6；包位于同级 `packages/`，包含宿主、Loader、驱动及四个正式版插件。包名按组件 ID、内容版本及扩展名生成。客户端验证固定公钥签名、HTTPS 来源、大小、SHA-256 和声明的 AMD64 PE 类型。旧 `/mods/v1/` 保留，不向旧客户端推送不兼容目录。CI 不再内置私有组件。下载完成不等于已加载，卸载宿主服务也不代表 DLL 已从游戏地址空间移除。

## 深渊事件与验收边界

插件模式同时订阅 `combat.rounds.v1`：高危委托与 DIY 副本通过 SDK 的
`Clone_On_Reset_Request` → `Clone_On_Reset_Responded` 配对生成新一轮边界，
保留请求时的副本 ID、类型、难度及采集代次；拒绝、退出、换副本或重复响应不误切轮。
深渊将“重启当前半场 / 重置本关进度”的请求与阶段响应及 `IsReChallenge`
读回配对，不依赖该布尔值每次都先恢复为 false。继续挑战和普通上下半切换不算重开。
边界与命中保持 FIFO 顺序。深渊“重启当前半场”只清当前半场的失败尝试，
另一半场继续保留；“重置本关进度”才归档整轮并清上下半。
高危委托和 DIY 重置仍归档旧轮、清空战斗统计。装备数据保留；
没有战斗数据时不额外生成空历史。三种副本的真实操作仍须分别实机验收。

插件实时链路使用 Capture pipe 的 `combat.abyss.v2` 能力及
`event.combat.abyss` 通知，不依赖旧整份报告中的 `abyss.transitions`。
当前客户端额外要求 `combat.abyss.restart_scope.v1`，协商 `abyssSchema:3`，
将 `restart_half` 与整层 `restart` 明确区分；不向旧客户端降级成整层重置。
上下半、重开、成功、退出和命中共用有界 FIFO 与通知序号；重开和切半不会因为
批次合并或首个游戏时钟尚未到达而越过已有命中。Rust 复用既有领域 reducer，
不在 React 中另建深渊状态机。

原生观察本地玩家的 `HTPlayerState.ClientAbyssCloneResponse`，在游戏原处理函数
解码参数后读取玩家状态中的深渊数据；不再把通用 `ClientSyncCloneCustomData`
当作深渊同步路径。上下半场通知仍来自已确认的深渊委托。
`AbyssGamePlayData` 的运行时类型、尺寸、字段偏移和类型均经反射校验；
`IsReChallenge`、成功标记和实际楼层直接来自该结构。重置/退出不以按钮点击、
角色切换、伤害归零或时间接近推断。读回重复状态不重复清空统计。
换层时临时的 `None` 不等于退出；退出以明确服务器通知或已知深渊的副本状态
变为离开为依据。开始采集后通过既有游戏线程脉冲读取当前副本状态，随后最多每秒一次，
以 `location` 事件补充错过的场景/楼层信息；只确认楼层时不伪造上下半。
环境快照的 `abyssRuntime` 提供读取状态与可空的上下半。当前状态从 SDK 响应实现中
定位：参数解码目的字段与 `OnAbyssFightStageChanged` 的来源字段须匹配，且运行时
结构反射及副本身份校验通过；不写死游戏 RVA 或玩家字段偏移。
`GetAbyssFirstDataLayerLoaded` 只表示数据层加载，不被当作上下半枚举。
无法证明的期数、上下半和缺失边界保持未知。

旧战斗插件缺少 `combat.abyss.v2` 时，新客户端会明确拒绝启动插件采集；
须更新战斗插件和客户端后再测试。队列溢出、身份变化或畸形事件失败保持可见，
不会静默回退抓包。构建和隔离回归不代替实机验收；需验证上半、当前半场重开、
下半、整层重开、成功和退出，期间不应混入上一轮伤害。
